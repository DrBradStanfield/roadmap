Brad asked for the automatic tests to be made better and faster: "look for stupid tests etc that make no sense or are out of date or wrong".
This is step 1, a survey. Nothing was deleted or rewritten here. Fable rules on each row; fixes land as small PRs by area.

## Where CI's time goes

- CI splits the 793 test files into 6 shards by file count. PRs run in UTC only; pushes to main add Los Angeles.
- A PR's tests finish when the slowest shard does. On PR run 43347278593, shard 2 took 255 s and the other five 77-105 s.
- Single files set that pace:

| File | CI seconds | Why |
|---|---|---|
| app/lib/matched-content.test.ts | 234 | One sweep over every ordered pair of 113 masters rebuilds each master's reduced text about 340,000 times; only the raw text is cached (A01) |
| ios/scripts/release-engine.test.ts | 178 | 14 full engine builds of about 12 s each; 8 only test a refusal that runs after the build (C01); each build spawns 24 parity processes (C02) |
| tools/test-chatbot-matching.test.ts | 103-131 | 34 spawns of the whole harness through tsx (T01) |
| tools/codex-review.test.ts | 41-65 | Two node starts per test, 74 temporary git repos, fixed sleeps (T07) |

- Fixing those four would bring every shard to about 105 s: about 150 s off each PR run.
- The web widget's HealthTool tests take 404 of the widget's 554 CI seconds. Rendering is not the cost. They wait out the app's real debounces (500 ms field save, 300 ms list save, 800 ms store write, 800 ms auto-advance, 3-3.5 s glow, 5 s re-read throttle) in real time (W01). Six files already use fake timers; extending that saves about 165 s of CI time, spread over the shards.
- Shard 2 runs about 1.6 times slower in the Los Angeles leg for every file in it, so that is the runner, not the time zone.
- The estimated savings across all 42 slow rows add up to about 850 CI seconds per time-zone leg.

- Order dependence: two leads found order-dependent files the same day (T7, issue 1333; storage-copy, X02). CI never runs the suite shuffled (X03).

## For Brad (workflow changes; none made)

- `us-products-bundles.test.ts` runs a full Vite build on both time-zone legs, though its result cannot depend on the zone (W13).
- Sharding by duration instead of file count would balance the shards.
- A nightly run in shuffled order, printing its seed, would catch order dependence (X03).
- The Pages-build Sentry filter check, and the macOS-only suites, never run in CI (W23, T23).

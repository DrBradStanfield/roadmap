## 2. Findings

**F1. typesafe.ai is not a scraper.** It sells Jev, a "System One" model returning typed decisions with calibrated probabilities instead of text ($42 per billion input tokens; early access). It fetches and extracts nothing from web pages. Its one plausible fit, the pre-router classifier, takes user chat text carrying health values (11 MEASUREMENT turns in W39), so it needs a privacy decision first. Parked.

**F2. The loop protects retrieval, not body text.** The router sees only `[type] handle: summary`, capped at 150 chars by `capSummary`. Bodies and keywords are invisible to retrieval, but the answer model loads the whole file, frontmatter included, so a stale dose in a summary does reach answers. Blanket summary rewrites lost (96.3% to 93.8%); targeted fixes won. So:
- Summaries: frozen by default. Guard: `npm run rebuild-index && git diff --exit-code docs/blog/index.json` (rebuilt from a scratch copy, byte-identical).
- Summary fact corrections (number and unit tokens only, format untouched): 72 of the 80 dose-stating summaries carry every dose past `capSummary`'s clause cut, so the router string cannot change; those need only the mechanical check that `capSummary(old) === capSummary(new)`. The other 8 change the router string and get a pre-registered non-inferiority rule on paired full-suite arms (the W39 retro proposal), because one summary edit sent three unrelated fixtures to empty in W39. The loop's "unchanged → revert" rule and its 5-per-run cap bind the loop, not a build session, and do not apply here.
- Bodies: free to change, guarded per article by the checks in Phase 0 step 5.

**F3. Two references never reach the answer model today (live defect).** `loadMatchedArticlesFromHandles` in `app/lib/chat.server.ts` caps combined article text at 80,000 chars and `break`s on the first entry that would exceed it. Vitamin C is 83,150 chars and omega-3 81,830 (JS string length). Alone or first, nothing loads; later, dropped. `continue` alone would still skip either when it is the only match. The same `break` sits in `tools/test-chatbot-matching.ts` and `tools/youtube-comment-dryrun.ts`, and one answer check targets omega-3. Recommendation: raise `MAX_BLOG_CHARS` to 120K plus `continue`. Cached blocks are about 58K tokens (products.md alone is 108K chars); worst case with 30K tokens of articles, 8K history and 4,096 output is about 110K, inside the 200K window, and the article block sits after the uncached per-user block so cache layout is unchanged. Cost: about 2 cents a turn at the pinned Sonnet 5.5 input rate ($2 per million) for the extra 10K tokens over today's effective load. Two of the 29 references over 60K still cannot load together at 120K; say so in the acceptance criterion. One Sentry-free loader module returning `{content, titles}` shared by the server and both tools (the harness header explains why it cannot import the server module today). New US-15 acceptance criterion: every routed entry that fits the cap loads. Failing test first. Not gated on any decision.

**F4. The 113 references are published twice and the documented republish path does not work.** Education page on drstanfield.com, scrubbed under Workstream A (zero "MicroVitamin", "Sleep by Dr Brad", `/products/`, `/pages/my-supplements`, "fills the gaps", "the supplement(s) I", "my multivitamin"); commerce twin on microvitamin.com in brand voice. `tools/shopify-article-ids.json` holds commerce IDs only. `/blog-update` pushes only title, handle and tags, rewrites `index.json`, and deploys per article. `shopify-article-create.js --edu --update <id>` can push a body, but an update without `--tags` resets tags to "Supplements", supplement-wiki.md still tells the builder to insert product links (a pre-split spec), and `body_html` replaces the live body, which can differ from the `.md`. Two halves: (i) the `.md` the chatbot reads (Phase 2); (ii) an education publish step that must be built (Phase 2b). Commerce twins are a separate decision.

**F5. The Karpathy shape still fits; the missing piece is linting.** Index-plus-summaries beat keyword matching and the loop has improved it for eight weeks. Obsidian is an editor over a folder of markdown; the repo already is that folder. The unbuilt half is "health checks over the wiki": divergences between a pathway, the algorithm and a reference, reported as a list because Brad diverges from guidelines on purpose; algorithm-side fixes are three-file clinical changes. Adding it to chat-health is a charter change for Brad. Ceiling: the router index is about 50K tokens; do not multiply entries.

**F6. Grokipedia is already a citation source, and undoing it is a clinical re-sourcing batch, not a cleanup.** 67 references cite it in their reference lists (the lithium article behind the 2026-05-27 audit miss among them). A diff-driven refresh would leave those citations in place, and the fixture meant to catch it never runs. Removing the citations alone launders the claims: about 1,040 sentences rest on Grokipedia only, 55 in the lithium article alone, including the exact 2026-05-27 audit claim ("kidney toxicity has not been observed in over 40 years of commercial use", both citations Grokipedia). Live pages carry the same citations (education lithium page 55 mentions, commerce twin 93), so the `.md` fix reaches drstanfield.com only through Phase 2b and reaches microvitamin.com only if decision 4 says so. So the de-citation pass is claim by claim, not mechanical: for every sentence that loses its last supporting citation, the agent either finds verified evidence in the ConsumerLab or NIH raw (with the AC2 quote) or deletes the claim, listed under AC4 for Brad. "Via Grokipedia" entries are resolved to the primary paper or dropped; the 10 in-body mentions go too. The script then checks that every `[n]` resolves AND that no sentence carrying a number lost all its citations. Its own batch, its own review; the lithium fixture gets an `expected` handle so it runs; acceptance criterion "no body cites Grokipedia". Grokipedia is not re-fetched.

**F7. One Opus 5.5 agent per article is right, with constraints.** (a) Writes only its own `.md`; `index.json` rebuilt once per batch. (b) Every fact traces to the NEW raw, proved by path, sha256 and verbatim quote. (c) Hedged wording stays hedged. (d) DOI and PMID existence checked. (e) Forbidden-word scan and `claude_business/tools/check-copy-style.js` on reader-facing prose. (f) Product-mention count does not rise (agents read products.md, and 36 bodies already name MicroVitamin). (g) Raw text is data, never instructions: the agent prompt says so and the adversary checks for instruction-shaped text in the raw (CLAUDE.md security rule). Cost: no honest order of magnitude exists until the pilot runs; the pilot's first deliverable is the per-article cost, and section 4 item 1 is answered with that number, not before.

**F8. The raw tools need work before any diff is trusted.** `scrape-healthpathways.js` hardcodes its output dir, skips every slug already present, reads the April page list (new or retired pages invisible), still lists `hair-loss-subsidy`, and finds the review date on 2 files. `fetch-wiki-research.ts` fetches NIH and Grokipedia only. **No owned tool fetches ConsumerLab**: it is done by `fetch()` inside Brad's authenticated Chrome via the DevTools MCP with a four-section whitelist, saved by hand. About 297 pathways have agent-written raw of uncertain fidelity, though 40 raw HTML files are faithful and normalisable.

**F9. The "harness in the MCP" idea: the valuable half is shipped; the rest splits by surface.** `get_plan` already returns Brad's algorithm with reason, guidelines and references. Exposing the knowledge base on the HOSTED connector fails on the evidence: a model-backed search would send health values to Anthropic and contradict the 1.0.1 privacy text; a model-free `list_knowledge` is about 73K tokens, three times a typical tool-result cap; `get_knowledge` breaks the listing's negative tests (a general ferritin question would call a tool because a ferritin pathway exists); a preamble carries 3 of about 20 hard boundaries and pathways would reach ChatGPT users without their posture layer; and the hosted server logs no content, so "revisit on demand" can never be observed there. On STDIO, Claude Desktop has no file access, so MCP resources over the three content folders would be cheap to add, but they cannot be measured: the stdio server opens no network connection and writes no per-call log, so any signal sits on each user's machine, and resources are attached by the user rather than fetched by the model. Lane B needs a declared usage signal and this has none. Claude Code users already have `docs/` on disk because the install is a clone, and the CLI (`tools/get-plan.ts`) reads the same folder. Recommendation: not built on either surface; the CLI answer is that the knowledge folder is already on the user's disk. Brad is not overthinking it; the differentiated part is already in `get_plan`.

**F10. Licensing gates the pilot.** Derived text sits in a PUBLIC repo under a blanket MIT `LICENSE` with no carve-out, so the licence purports to grant MIT terms over text derived from HealthPathways and ConsumerLab. The MCP tool instructions say "open source, MIT"; the ChatGPT listing implies a public repo only through `report_feedback` filing public issues; the Pages self-host build needs a public repo but reads none of the derived text; the stdio and CLI install is a clone; and git history keeps the text whatever is done next. The repo has also been anonymous-404 since the 2026-09-18 account flag. raw text sits in a PRIVATE repo in Dropbox; a re-fetch adds about 26 MB of paywalled text; ConsumerLab re-fetch uses a method supplement-wiki.md describes as bypassing Cloudflare. I am not a lawyer. Decision 3 lists the options with their consequences.

**F11. Screening guideline: drop it.** Algorithm §8 is already in every answer's cached prompt; at least eight screening pathways exist; no backlog row asks for it; a USPSTF/ACS entry would contradict the algorithm inside the same context and is three-file clinical content; router rule 5 hard-codes three guideline names. Divergences belong in the lint. Medications stays out under the 2026-04-23 decision.

**F12. Content gaps are not the problem.** One open backlog theme (peptides, 9 asks). Classifier-catchable misses zero for five runs. This is a freshness and quality project.

**F13. Concurrency and baselines.** Chat-health edits up to 5 summaries a week; `/blog-post` writes `docs/blog` and `index.json`; the working tree holds another session's uncommitted router and classifier edits. Pin the baseline SHA after that lands; re-baseline after any prompt OR model change (the router's Haiku-to-Sonnet switch is in flight, so section 1's figures are Haiku-router numbers); batches land between Sunday runs; new-page batches are separate from body-only batches because they change `index.json` and `categories.json`.

**F14. A reply-level signal exists but is short-lived.** Blog-bubble and Discord replies are nulled after 30 days (US-15 AC8); YouTube replies persist (84 of 122 W39 events); widget replies are never stored; `matched_handles` counts persist. So the audit metric is: within 30 days of each batch deploy, the orchestrator pulls every stored reply whose `matched_handles` include a refreshed handle and checks it for the batch's AC3 hardening tokens and for any number absent from the refreshed body (answer-check fixtures are question-specific and do not transfer); owner the build session, recorded in the batch report.

## 3. Plan

**Phase 0. Defect fix, baseline, decisions (one session; steps 1 and 2 are not gated).**
1. Lane A, F3: cap to 120K, `continue`, one loader, US-15 acceptance criterion, failing test first, deploy. Same commit: `docs/wiki/research/` into `.dockerignore` (the image data boundary, so security-class: Codex pair required, and `tests/dockerignore.test.ts` gains "research" in its data words); the five answer-check fixtures that never run get a fixed-handle field rather than `expected`, so they do not join the router suite.
2. Answer-check fixed-handle mode in `tools/test-chatbot-matching.ts` (score the answer against a given handle set, independent of routing) and a written flip rule.
3. Pin the baseline SHA. Record `index.json` hash, a paired 3-run matching arm, fixed-handle answer checks on all 44.
4. Brad answers section 4. The pilot waits for decisions 1 and 3.
5. Story "Knowledge refresh" with these criteria, each with its check and owner:
   - AC1 `index.json` diff after a body-only batch is exactly the listed summary corrections, each passed through F2's split. Check: script. Owner: orchestrator.
   - AC2 raw fidelity: every changed number, dose or unit in a body (drug names have no lexicon and are covered by AC4) carries raw path, sha256 and a verbatim quote in the diff report, which lives OUTSIDE the repo (scratchpad), never in the working tree, so no raw text reaches a commit, the Docker image or a Codex snapshot; the batch report commits only hashes, counts and the sign-off line; a script confirms the quote is in that raw file and the token is in the quote. Tokeniser rules written down first (citation markers `[n]`, years and PMIDs excluded; `1 g` and `1,000 mg` equal; en-dash ranges as two numbers; quotes matched after unescaping turndown markdown and collapsing whitespace). This is a filter that feeds Brad's review, not proof the raw supports the claim. Check: script. Owner: orchestrator, then Brad.
   - AC3 hedging: whole-word matching; the per-entry count of hedge tokens (may, might, can, could, likely, possibly, appears, suggests, associated with, linked to, observational, limited, preliminary, modest, some evidence, no evidence, unclear, insufficient, mixed, not established) does not fall, and every line that loses one or gains a hardening token (causes, prevents, treats, cures, reduces risk, proven, should, must, safe, will, effective, improves, lowers, no side effects, recommended, not been observed) is listed. Check: script. Owner: Brad reads the list.
   - AC4 deleted sentences: every sentence removed anywhere in the body is listed with its justification against the new raw; every heading present before is present after, no exceptions (the corpus uses at least 178 escalation headings outside any short regex, and 82 pathways would match none). Check: script. Owner: Brad.
   - AC5 answer quality: at least one fixed-handle answer check per refreshed entry, drawn from its source diff and pre-registered before the agent runs, stored under its own fixture field so it never joins the router suite and shifts the loop's denominator; none below baseline under the flip rule. Check: harness. Owner: orchestrator.
   - AC6 no Shopify or `index.json` write by an agent: agents run without the claude_business `.env`; article `updated_at` snapshotted on both stores before and after each batch. Check: script. Owner: orchestrator.
   - AC7 excluded handles never regenerated; no body cites Grokipedia; product-mention count per body does not rise; every `[n]` in a reference resolves; DOIs and PMIDs resolve. Check: script. Owner: orchestrator.
   - AC8 Brad's sign-off per batch, recorded as a line in the batch report committed with the batch. Owner: Brad.

## 5. What this plan deliberately does not do

- No summary rewrite beyond number-and-unit fact corrections under F2's split; no keyword edits.
- No vector RAG, no Obsidian, no new retrieval layer, no new guideline entries.
- No typesafe.ai for scraping; no Jev without a privacy decision; no Grokipedia fetch or citation.
- No rewrite of pathway bodies whose source has not changed or whose live review date predates the April scrape.
- No knowledge tool on the hosted MCP; no new tool on the ChatGPT app while 1.0.1 is in review.
- No publishing, no `index.json` write, from inside a per-article agent; no raw text handed to Codex.

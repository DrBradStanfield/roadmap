`e2861050f14d58`, Fly `syd`. Request: `POST https://health-tool-app.fly.dev/api/chat`
(the Fly host directly), `User-Agent: curl/8.6.0`, `query: []` — no
`signature`, `shop` or `timestamp` — `Content-Length: 50`, JSON. Stack:
`action` (api.chat.ts:617) → `reportChatError` (:39).

Without a signature, `getAuthOrGuest` → `getAuthenticatedUser` →
`authenticate.public.appProxy`, which rejects by THROWING a 400 `Response`
(`@shopify/shopify-app-react-router@1.2.0`, `appProxy/authenticate.js:17`,
verified from the package tarball — no node_modules in the container). The
route's outer catch-all treated it as our failure: Sentry event + 500.
react-router 7.18.3 returns a thrown Response as-is and never calls
`handleError` (`handleQueryRouteError`), so the framework's own path is silent.
The four sibling `appProxy` callers (`api.events`, `api.ab`, `api.feedback`,
`api.measurements`) call it outside any `try`; chat alone had the defect.

The requests' minute matches Brad's commit `7bf840e` ("say how to verify",

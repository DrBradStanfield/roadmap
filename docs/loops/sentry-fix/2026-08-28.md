## Root cause (claimed issue)

`tryAcquireCronLock` returned the same `false` for "lost the day-lock race"
and "lock query errored"; every cron caller maps `false` to `lastRunDate =
today`. One transient PGRST303 therefore made the erroring machine mark the
day done and silently skip its daily job (reminder emails, trending, ops
summaries) unless the other machine happened to win the lock.

PR: https://github.com/DrBradStanfield/roadmap/pull/35 (Tier 3 pipeline,
branch `claude/sentry-fix-cron-lock-day-skip`). US-28 added to
docs/user-stories.md (+html regenerated). Transient lock errors now throw
(US-27's fail-distinguishably convention); reminder-v2's acquire moved inside

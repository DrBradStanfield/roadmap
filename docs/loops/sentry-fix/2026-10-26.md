## Escape analysis

Why could this run not name the cause? `fetchAnthropicRaw` cancels every
error body ("errors may echo uploaded or chat content"), so Sentry sees
only the status. The 2026-09-25 report proposed keeping Anthropic's
`error.type` (a closed set: `invalid_request_error`, `billing_error`,
`rate_limit_error`, ...). It was never built. Today it would have told the
two apart in one event. Re-proposed (Tier 0; it changes a privacy choice,
so Brad decides): read the error JSON, keep `error.type` only as a Sentry
tag, drop `error.message`. No new test catches an account-level outage. A
synthetic check (one tiny call a day that pages on failure) is the
missing guard; that is a monitor, outside this loop's scope.

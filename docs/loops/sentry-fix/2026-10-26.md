## Escape analysis

Why could this run not name the cause? `fetchAnthropicRaw` cancels every
error body ("errors may echo uploaded or chat content"), so Sentry sees
only the status. The 2026-09-25 report proposed keeping Anthropic's
`error.type`, a closed set. It was never built: a report-only proposal got
lost. Today it would have settled the cause from one event. Re-proposed,
now in decision issue form: read the error JSON, keep `error.type` only as
a Sentry tag, drop `error.message`. It is in the Tier 3 grant, but it
changes a privacy choice, so Brad decides. No unit test catches an
account-level outage; a daily one-call synthetic check that pages on
failure is the missing guard (a monitor, outside this loop's scope).

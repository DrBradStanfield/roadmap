## Root cause (from event data)

Server event, `platform=node`, tags `feature=youtube-bot`, `handled=yes`,
machine `e2861050f14d58`, Fly `iad`. Google's Data API answered one
`GET /youtube/v3/comments?parentId=…` with HTTP 503 and the body
`"The service is currently unavailable."`. The other 18 `listReplies` calls
in the tick returned 200 in ~100-250 ms; the 503 arrived after a 30 s hang
(last 200 at 09:53:19.3Z, 503 at 09:53:49.4Z) — a Google-side stall, not a
malformed request. It was the 19th of 19 threads, the oldest in the 7-day
follow-up window. Stack: `listReplies`
(youtube-bot.server.ts:285) → `processFollowUps` (:947) → `tick` (:1183).

The call site is designed for this: `processFollowUps` wraps each thread's
`listReplies` in try/catch, calls `logTickError`, and `continue`s to the next
thread. `fetchRecentPostedThreads` rebuilds the thread list every tick, so the
skipped thread is re-scanned on the next half-hourly tick. The degradation
direction is "no post this tick", not a value that feeds a cap or lock
decision — nothing fails open (the PGRST303 class does not apply). The thrown
message already truncates the upstream body to `status + 200 chars`, so the
grouping problem the 08-12 learning flagged for HTML pages is absent here.

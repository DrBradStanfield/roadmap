**Proposal (Tier 0: `app/entry.server.tsx` is outside the grant).** Skip
404 route misses in `handleError`, except paths that can be ours:

```ts
import { isRouteErrorResponse } from 'react-router';
// in handleError, before captureException:
const { pathname } = new URL(request.url);
if (isRouteErrorResponse(error) && error.status === 404 &&
    !/^\/(api|apps|\.well-known)\//.test(pathname)) return;
```

About +3 prod LOC, nothing deletable. Options: (A) drop all 404s, simplest,
loses the stale-caller signal; (B) the sketch above, keeps it;
(C) do nothing, accept a noisy 6X. Recommendation: B. Unverified: whether a
route miss reaches `handleError` as an `ErrorResponse` with status 404 (the
title `getInternalRouterError` suggests so). The build session must confirm
it with a test before shipping. Decision issue opened (link in the brief).

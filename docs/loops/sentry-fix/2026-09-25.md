## Root cause (from the event, confirmed in code)

`main()` awaits `resolveBackend()` before rendering, and `resolveRemembered`
read the remembered provider with a bare `localStorage.getItem`. The field
sent every way that read can fail: the global missing (6T), the getter
throwing (6N), the property `null` (6J). `lib/storage.ts` already had
`safeGetItem`/`safeSetItem`/`safeRemoveItem` for exactly this; the
remembered-backend key was the one caller on the load path that bypassed
them, on nine sites across four files. Why Safari reports the global as
missing rather than a SecurityError: I don't know; the fix covers every shape.

**PR:** [#121](https://github.com/DrBradStanfield/roadmap/pull/121) —
US-09 AC16. `rememberedBackend` / `rememberBackend` / `forgetBackend` in
`connect.ts` on the safe accessors; `resolveRemembered` moved there, rebuilt
on the existing `adapterFor`; all nine `BACKEND_KEY` sites swapped. Second
half: the device persist capture carries a closed-list `cause` tag
(QuotaExceededError | SecurityError | TypeError | ReferenceError | other),
so 6M's quota-versus-blocked question is readable next run. Prod LOC

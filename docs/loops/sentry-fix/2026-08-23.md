## Root cause (from event data)

All six events are one actor (same UA: Chrome 151 / macOS 10_15_7, Sentry geo
`country_code: US`; the `Fly-Region: ams` header is the ingress PoP, not the
actor) manually probing the Shopify OAuth exit-iframe endpoint on
`health-tool-app.fly.dev`:

- 20:12 — `?exitIframe=javascript:alert(document.domain)` ×2
- 21:51 — `?exitIframe=data:text/html,<h1>a</h1>…` built up keystroke by
  keystroke over 11 s (4 variants)

Classic open-redirect / XSS payloads. Each was rejected server-side by
`@shopify/shopify-app-react-router`'s `sanitizeRedirectUrl`
(validate-redirect-url.mjs → renderAppBridge → respondToExitIframeRequest),
which throws before any redirect or render — Sentry marks the event
`handled: yes`. The error IS the defense firing. The YouTube-bot breadcrumbs
in the event are process-global noise from the same server, unrelated.

**Verdict: wontfix.** The probed `javascript:`/`data:` payloads are all
rejected — no user impact, no code change warranted for these events.
`app/routes/auth.$.tsx` is auth code, excluded from this loop's Tier 3 grant
regardless, and suppressing the capture would delete a useful probe-activity
signal. Not decision-worthy: routine internet background probing, the probed
vectors held; no issue opened.

Scope note (adversarial review): "no vulnerability" would overclaim.
`sanitizeRedirectUrl` (@shopify/shopify-app-react-router 1.2.0,
validate-redirect-url.mjs) validates the URL **scheme only** —
`VALID_PROTOCOLS = ['https:','http:']`, requireSSL default true — not the
destination host. `renderAppBridge` calls it with `options={}`, so
`?exitIframe=https://evil.com` passes and renders
`window.open("https://evil.com","_top")`: a reachable **arbitrary-host https
open redirect**. It stays low: it is Shopify library behavior (every Shopify
app inherits it), the destination is `JSON.stringify`-escaped (redirect
vector, not XSS), and the route is grant-excluded (propose-only). Recorded
here as a Tier 0 proposal, not fixed. The six triaged events are genuinely
handled rejections regardless — the open redirect needs a valid https host,
which none of them supplied.

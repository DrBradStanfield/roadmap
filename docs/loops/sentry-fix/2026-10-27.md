## The fix (77)

PR #288 (`claude/sentry-fix-77-persist-cause-class`, head 1f0a70ce). The
pipeline's reviewer approved the first head (2450f67e, CI green); the
second commit restarted CI and review. Not merged by this loop.

Real device-tier shapes, pinned by tests on `LocalStorageAdapter`: corrupt
read before the write → SyntaxError; lost-update storm → ConflictError;
logout stop → none; corrupt read-back after the write landed → other (the
save wraps it twice). Full disk keeps `cause=QuotaExceededError`. The
once-a-session dedupe key now includes the wrapped error's name, so a
second kind of refusal in one session still reports
(`record-session.ts`, +1 code line). Net prod LOC for the PR about +12 code
lines (+21 raw); nothing deletable.

Root cause: not yet knowable. `cause=other` pools about seven refusal kinds
(conflict storm, verify failure, corrupt local data, logout stop, schema
too new, merge throw, an odd DOMException). The PR adds `errorClass` and a
closed `causeClass` tag, both value-free, and puts the new key on the scrub
allow-list. The next event names the class; the fix follows from it.

**Escape analysis.** Missing observability, not a missing test of
behaviour: the persist capture was tested only against the coarse `cause`
tag, and nothing pairs a new tag with the scrub allow-list, so a tag added
without it vanishes silently. The PR's test asserts the tag survives the
scrub, which closes that half of the class.

## The process in one screen

1. **Work**: `sh tools/worktree-new.sh <name>`, then EnterWorktree `path`. Commit, push
   (`git push -u origin HEAD`, on its own line), open a PR. Add `hold` to any PR you don't want
   auto-ship to merge.
2. **Review by class.** Clinical, merge/FHIR, security, agent-contract or workflow changes get a fresh
   `adversary` agent plus Codex (`node tools/codex-review.mjs --range origin/main..HEAD --out <file>`).
   Everything else gets one adversary (a doc sweep of your own may skip it; a contributor PR never
   does). A change to `.github/workflows/**` also needs Brad's explicit yes, and a clinical change
   needs his yes on the exact words, before merge. Brad asked for Codex on
   `--model gpt-6-astra` for the 2026-11-06 process round, because it mattered; the default model
   is otherwise fine.
3. **Cap**: one full review, then one re-check scoped to the fixes. Anything still open goes to Brad,
   with both positions and your recommendation.
4. **Before merge**: every open finding becomes a `review-note` issue (security or privacy findings go
   to a draft private advisory instead). The PR body lists the issue numbers.
5. **Merge gate**: CI green on the PR's head. If main has since changed a file the PR also changes,
   merge main in, push, and wait for CI again. Merge only with
   `gh pr merge <n> --merge --match-head-commit <full sha>`.
6. **Deploy** once per batch of merges (`gh workflow run deploy.yml`, never while a Deploy runs), then
   report the sha, each stage's result and the live checks to Brad. The server reads files under
   `docs/` and `tools/` at runtime (blog index, products.md, the knowledge search), so a docs or
   tools change can need a deploy too; only a CI-only or test-only change never does. After a merge
   that touches `roadmap_text.html`, also hand-publish the changed section to
   drstanfield.com/pages/roadmap and run `node tools/roadmap-page-drift.mjs` until it prints IN SYNC
   (git-workflow.md step 5, US-64 AC16).
7. **Contributor PRs** (Austin, `robertaustinbell`, from a fork): triage by class, pin each head SHA,
   build batches with `node tools/merge-batch.mjs <list-file>`, open the batch PR with `hold`, one CI
   run, one merge, one deploy. Send a rejected PR back with a comment saying why.
8. **Finish**: `bash tools/worktree-done.sh <name>` from the main checkout once the PR has merged.

## Lessons learned (2026-11-04 to 2026-11-09)

1. **GitHub enforces; hooks only warn.** Three rounds each on two push-guard PRs (805, 930) closed
   some bypasses and opened others: bash has too many spellings for a text parser. Main had no
   protection at all until the ruleset of 2026-11-09. Put a hard rule where the server enforces it.
2. **Codex must diff from the merge base.** It once diffed against `origin/main` after another PR
   landed and read that PR's change as reverted: a false block on PR 919. Fixed in #921.
3. **Parallel PRs clash on AC numbers.** Take the next free AC number on main at push time, and check
   again after merging main in.
4. **"fatal: stash failed" in a new worktree** is macOS tagging new files (`com.apple.provenance`),
   which changes their ctime. merge-batch merges with `core.trustctime=false` (#931).
5. **Tests assumed the machine's zone and locale.** 153 failed in Los Angeles and 28 more in UTC−12 or
   UTC+14, all test assumptions, no product bugs. Tests now start in `en-GB`, and CI runs in UTC and Los
   Angeles (#932, merged 2026-11-09). The 28 fixed-clock fixtures are a follow-up.
6. **Check a subagent's trace before giving Brad a decision.** #938 read `record-edits.ts` without the
   tool schemas and called a fixed problem open. Checking it took three greps.
7. **Deploys cancel each other's live check.** If yours is cancelled, check that the newer deploy
   contains your merge and passed every stage.
8. **Hold your own PRs** while their merge order matters. Auto-ship merged three early.
9. **Spawn subagents from the main checkout.** An agent is pinned to the folder the orchestrator is
   in when it starts, and loses its shell if that worktree is removed.
10. **The push guard refuses a heredoc with an apostrophe.** Write the text to a file with the Write
    tool instead, and push on its own line.
11. **Frame an adversary as a regression check, not "break it".** A safety classifier stopped the
    first #930 adversary over the wording.
12. **The review cap holds.** Past the cap, the decision is Brad's. Give him both positions, the
    options and a recommendation, never a bare "accept?".
